# 2x4 integration

2x4 is an optional assistant connection for BRA status, chat, and controlled engagement actions.
Boots mediates its access to the engagement.

## Chat relay

The browser reads transport settings from `GET /api/config`.
For `numbuh_2x4_ws`, it connects to the Boots route `/ws/chat/numbuh_2x4`.
Boots selects the configured OpenClaw gateway or Hermes service.
Provider credentials stay on the server.

If relay configuration is incomplete or the connection fails, the browser uses the legacy chat queue.
Legacy chat uses `POST /api/chat`, `GET /api/chat/pending`, and `POST /api/chat/respond`.

| Setting | Function |
| --- | --- |
| `chat_provider` | Select `legacy_api` or `numbuh_2x4_ws`. |
| `numbuh_2x4_enabled` | Enable the gateway connection. |
| `numbuh_2x4_ws_url` | Set the upstream WebSocket URL. |
| `numbuh_2x4_token` | Supply the upstream gateway token. |

Legacy `openclaw_*` settings remain accepted aliases.
The upstream agent selection is separate from the browser transport selection.

| Setting | Function |
| --- | --- |
| `numbuh_2x4_agent_provider` | Select `openclaw` or `hermes` for chat. |
| `numbuh_2x4_hermes_base_url` | Set the Hermes service address. |
| `numbuh_2x4_hermes_session_key` | Select the Hermes chat session. |
| `numbuh_2x4_hermes_api_key` | Supply the Hermes service key when required. |
| `numbuh_2x4_call_agent_provider` | Select the call integration provider. |

For Hermes chat, Boots builds an HTTP request to the configured service.
For OpenClaw chat, it maintains the upstream WebSocket relay.
Both paths use the browser connection to Boots.

## Bounded control API

The control plugin uses `bootsBaseUrl` and a dedicated `bootsServiceToken`.
The service token is separate from the browser access token.

| Route | Function |
| --- | --- |
| `GET /api/2x4/summary` | Read the bounded engagement summary. |
| `GET /api/2x4/file` | Read an allowed document identifier. |
| `GET /api/2x4/log` | Read an allowed log tail. |
| `GET /api/2x4/engage-status` | Read engagement status with a takeover lease. |
| `POST /api/2x4/engage-action` | Request an engagement action with a takeover lease. |
| `POST /api/2x4/takeover-confirm` | Confirm a takeover request. |
| `POST /api/2x4/stand-down` | Invalidate the takeover lease. |

Allowed file identifiers are `scope`, `stats`, `report`, `findings`, and `precheck`.
The log identifier is `engage`. Takeover requests use the `x-2x4-lease-id` header.
Scope mutation approvals are denied during takeover.

## Takeover procedure

1. Request `Takeover` in chat.
2. Enter `Yes` within 15 seconds.
3. Check the active takeover status.
4. Send `Stand Down` to end takeover.

Confirmation is case-insensitive. The configured lease lasts 30 seconds. Action parsing accepts complete JSON objects.
Invalid action objects cause no operation. Query failures leave takeover enabled until expiry or stand-down.

## Call control

The WebSocket accepts `takeover_call_start` and `takeover_call_stop` messages.
It emits `takeover_call_started`, `takeover_call_stopped`, or `takeover_call_failed` events.
Call methods delegate to `voicecall_bra.initiate` and `voicecall_bra.end`.

The control API includes `/api/2x4/call/continue`, `/speak`, `/status`, and `/stop` routes.
The [voice plugin](../2x4/openclaw-2x4-voice-call-bra-dev/README.md) supports Twilio, Telnyx, Plivo, and a local mock provider.
Public telephony providers require a reachable callback URL.

OpenClaw calls use the installed gateway and voice plugin.
The Hermes path loads an installed `voice-call-bra` plugin from the Hermes plugin directory.
The provider integration supplies speech and media behavior; Boots supplies the engagement call actions.

The interface supports `engage` and `2x4` panels with `tabs` or `split` display modes.
Panel state updates apply to connected browser sessions.

## State and authority

The controller keeps active leases in the running server state.
Stand-down and expiry invalidate the lease.
An accepted action uses the existing engagement router rather than an unrestricted shell endpoint.

The service token, browser token, and provider token have different roles.
Use the dedicated service credential for bounded API clients.
